# 城市社区临时托管自习室 · 预约与安全巡查平台

面向城市社区临时托管自习室场景的一体化看护平台：家长在线预约 → 工作人员入场核验与座位分配 →
志愿者自习过程记录 → 志愿者/社区/家长/安保围绕同一协同事件处置 → 安全巡查 → 离场与家长电子确认 →
当日档案 / 看护时间线 / 周统计决策 / 长期异常学生重点关注名单。

技术栈：**Vue 3 + Vite + Pinia + Element Plus**（前端，nginx 托管并反代）、
**NestJS 10 + TypeORM**（后端）、**PostgreSQL 16**（数据库）、Docker Compose 一键部署。

---

## 原始需求

> 建设城市社区临时托管自习室预约与安全巡查平台，可采用 Vue 3、NestJS 和 PostgreSQL。家长为学生提交年级、到场时段、是否独自离场、紧急联系人、过敏或特殊照护需求后，平台根据自习室容量、志愿者排班、座位类型和社区开放时间生成预约。学生入场时，工作人员核验预约、家长授权、随身物品和离场方式；座位分配要考虑低龄学生、安静区、临窗区和监控覆盖。自习过程中，志愿者记录迟到、离座、借用充电器、临时外出、身体不适和家长留言。若学生未到、家长临时改接、晚间无人接、同学冲突、电子设备丢失或自习室临时停电，平台要让志愿者、社区工作人员、家长和安保围绕同一事件处理。离场后，签到、座位、异常、家长确认和巡查记录进入同一日档案，用于社区判断是否调整开放时段、增加志愿者或限制部分学生独自离场。社区负责人还可以按周查看预约使用率、异常事件和家长响应，决定是否开放周末、增加低龄陪护或缩短晚间独自离场权限。平台还要按学生、家长、志愿者和安保生成当日看护时间线，社区处理晚归、丢物或冲突时能回到入场、座位、巡查和离场证据。长期异常学生会进入重点关注名单，后续预约需要家长重新确认。

## 一、快速启动（Docker 一键部署）

```bash
# 1. 准备环境变量（可直接复制后按需修改）
cp .env.example .env

# 2. 构建并启动（db + api + web 三个容器）
docker compose up -d --build

# 3. 查看实际映射端口（宿主端口取自 .env 的 CC_PUBLISH_PORT，默认 3037）
docker compose port web 8080

# 4. 浏览器访问
#    http://<宿主IP>:<CC_PUBLISH_PORT>/
#    在本评审容器内验证时使用： http://host.docker.internal:<映射端口>/
```

停止与清理：

```bash
docker compose down          # 停止并删除容器（保留数据卷）
docker compose down -v       # 同时清空数据库数据卷（恢复到全新演示数据）
```

健康检查：三个镜像均内置 `HEALTHCHECK`（api 检查 `/api/health` 数据库连通性，
web 检查 nginx 首页，db 检查 `pg_isready`）；容器内服务均以**非 root 用户**运行。

> 数据库端口**不发布到宿主**，只在 compose 内部网络由 api 通过服务名 `db` 访问；
> 宿主只发布一个 Web 端口（容器内 nginx 8080 → 宿主 `${CC_PUBLISH_PORT}`），
> `/api/*` 由 nginx 反代到 api 容器。

首次启动 api 会自动建表并播种演示数据（幂等；清空数据卷后重启会重新播种）。

## 三、功能与需求对照

| 需求 | 实现位置 |
|---|---|
| 家长提交年级/到场时段/是否独自离场/紧急联系人/过敏/特殊照护 | 家长端「我的预约」表单（自动带出学生档案） |
| 按容量、志愿者排班、座位类型、社区开放时间生成预约 | `POST /api/reservations`：开放时间校验、班次在岗与看护名额、座位总量、时段合法性四重校验 |
| 低龄晚间独自离场限制 | 开放时间含 `soloLeaveDeadline`；预约与离场两处强校验并计异常 |
| 入场核验预约/家长授权/随身物品/离场方式 | 工作台「入场核验」对话框，三项必须勾选方可入场 |
| 座位考虑低龄/安静/临窗/监控 | `DbService.allocateSeat`：低龄→低龄区、申请安静→安静区、其余优先临窗区，全部优先监控覆盖位；支持手动指定 |
| 迟到/离座/借充电器/临时外出/身体不适/家长留言 | 工作台「自习记录」7 类事件；迟到按到场时段自动判定；家长端留言同步写入 |
| 未到/改接/晚间无人接/冲突/设备丢失/停电 跨角色同一事件 | 「协同事件」模块：7 类事件、统一消息板、升级联动、关闭归档；四类角色均可发言 |
| 未到/晚间无人接自动发现 | 定时任务每 10 分钟扫描（超时 30 分钟未入场→未到事件；超计划离场 30 分钟家长未来接→自动升级事件） |
| 签到/座位/异常/家长确认/巡查进入同一日档案 | 「当日档案」页 + `GET /api/daily-archive`（含汇总指标与三类明细分页） |
| 按周看使用率/异常/家长响应，决定周末/陪护/独自离场 | 「周统计与决策」页：7 天使用率进度条、异常分类分布、家长响应率、自动运营建议 |
| 按学生/家长/志愿者/安保生成看护时间线，可回溯入场→座位→巡查→离场证据 | 「看护时间线」页：按学生折叠的完整时间线，证据/异常/事件入口标记 |
| 长期异常学生重点关注，后续预约需家长重新确认 | 异常分自动累计（≥8 进名单）；名单学生新预约为 `pending`，家长重新确认后生效；可手动管理 |
| 安全巡查 | 「安全巡查」页：区域、关联自习室、异常发现；进入档案与时间线 |

## 四、接口概览

- `POST /api/auth/login`、`GET /api/health`
- `GET /api/meta`（学生/房间/座位/开放时间/当日排班/座位占用）
- `POST|GET /api/reservations`、`GET /api/reservations/:id`
- `POST /api/reservations/:id/{check-in,check-out,events,message,parent-confirm,reconfirm,cancel}`
- `GET|POST /api/incidents`、`GET /api/incidents/:id`
- `POST /api/incidents/:id/{messages,escalate,resolve}`
- `GET|POST /api/patrols`
- `GET /api/daily-archive`、`GET /api/timeline`、`GET /api/weekly-report`
- `GET /api/watchlist`、`POST /api/students/:id/watchlist`
- `POST /api/{rooms,seats,schedules,shifts}`、`GET /api/volunteers`

## 五、目录结构

```
.
├── docker-compose.yml        # db（不发布端口）+ api + web（仅发布 CC_PUBLISH_PORT）
├── .env.example
├── api/                      # NestJS + TypeORM + PostgreSQL
│   ├── Dockerfile            # 多阶段构建，非 root 用户 + HEALTHCHECK
│   └── src/（entities / 各业务 controller / 定时扫描 / 幂等种子）
└── web/                      # Vue 3 + Vite + Pinia + Element Plus
    ├── Dockerfile            # 多阶段构建，nginx 非 root(8080) + HEALTHCHECK
    ├── nginx.conf            # SPA + /api 反代
    └── src/views/            # 家长/工作台/座位/事件/巡查/时间线/档案/周报/名单/设置
```
